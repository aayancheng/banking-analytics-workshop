# A decision is not a score

**Approve / Refer / Decline** = three layers, in strict order:

1. **Hard knockouts** — DSCR < 1.0, public records, deep delinquency → Decline, no appeal to the model
2. **PD zones** — model PD ≤ t_low → Approve · ≥ t_high → Decline · between → Refer
3. **Refer overrides** — thin DSCR margin, weak score, oversized request → downgrade an Approve, never upgrade a Decline

> Tonight you will measure — before being told — **how many decisions the knockouts made before the model ever voted.**

# Pricing is where the money happens — with no ML at all

The most valuable module in the platform is **deterministic arithmetic:**

```
interest income
− cost of funds          (3.5%)
− expected loss          (PD × LGD 45%)
− operating cost         (1.0%)
= pre-tax profit → net income → ÷ allocated equity → ROE
```

- **Break-even rate:** ROE = 0 · **Hurdle rate:** ROE = 15% — both closed-form
- Machine-precision unit tests, zero training, total auditability

> The pricing engine will find the biggest business number of the whole program in about four seconds.
