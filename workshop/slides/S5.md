# What validation actually asks

Not "is your AUC high?" — but:

- **Why should this model exist?** (purpose, materiality, alternatives considered)
- **What can't it do?** (limitations you found *before* the validator did)
- **How would you know it's broken?** (monitoring, triggers, escalation path)
- **Who signs?** (a name owns the outcome — always)

Even the pricing engine — **zero ML** — needs all four answers. Governance follows the *decision*, not the algorithm.

> **Regulators don't approve models — they approve people defending models.**

# How this platform was actually built

The reference build, real ledger on screen (no slideware numbers):

- **4 days · 8 sessions** — one phase per session: ledger → build → verify → log → stop
- **~90 agent dispatches, ~3.5M subagent tokens · ~$150 total** (published estimate)
- **~48% of tokens went to REVIEWS** — fresh implementer + two-stage review per task
- **104 backend tests + 14 end-to-end** as the merge floor, every phase
- Twice, an agent proved a gate unreachable and **reported BLOCKED** — a human decided

> The surprise of the agentic era isn't how much agents build.
> It's how much *judging* the human still does. **The bar goes up, not down.**

# The defense round

**10 minutes each, hard timer:** 5 min portal walkthrough + 5 min panel Q&A.
Panel = instructor + a peer with the challenge-question bank (20 questions, all fair game).

| Rubric (25% of final grade) | 1–5 |
|---|---|
| Lifecycle completeness — demo touches all five modules | |
| Decision reasoning — cutoff/pricing/gate choices defended **with numbers** | |
| Honesty under challenge — limits admitted; oracle ceiling cited where true | |
| Documentation quality — the pack supports every claim made out loud | |
| Agent direction — can explain what the agent did **and what they reviewed** | |

> Admitting a limit scores points. Bluffing loses them. That's the whole game.
