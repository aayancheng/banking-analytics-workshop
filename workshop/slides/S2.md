# Why banks still run WoE scorecards

Gradient boosting exists. Banks know. They still score with **WoE + logistic**:

- **Adverse action:** the law requires *reasons* — a scorecard's reasons are exact arithmetic, not an approximation of one
- **Effective challenge (SR 11-7):** a validator can re-derive every point by hand
- **Stability:** binned monotonic inputs age gracefully across cycles

> **Interpretability is a regulatory feature, not a performance compromise.**
> Tonight's evidence: the scorecard's AUC will land within 0.01 of the LightGBM challenger you'll meet next week.

# Alternatives to WoE + logistic

| Methodology | Discrimination (this book) | Reason codes |
|---|---|---|
| **WoE + logistic** (tonight) | **0.8176** AUC — measured | exact — `WoE × coefficient` |
| Gradient boosting (LightGBM) | 0.8096 AUC — measured (`adjudication/`) | SHAP — approximate, shifts under correlated inputs |
| Random forest | usually close to boosting, rarely better | same SHAP caveat, less mature tooling |
| Single decision tree | usually the weakest of the four | exact, but one tree = one fragile story |
| Neural net (tabular) | no consistent edge at this data size | needs a separate explainer bolted on |

LightGBM gets *more* inputs than the scorecard — including the scorecard's own PD — and
still loses.

> **More flexible ≠ more discrimination, here.** Extra capacity buys nothing and costs
> interpretability when the DGP is this close to linear (Session 1).

# Binning and Weight of Evidence

**Bin** a variable → compare each bin's default odds to the population's:

$$\text{WoE}_\text{bin} = \ln\frac{\%\,\text{goods in bin}}{\%\,\text{bads in bin}}$$

- Positive WoE → safer than average · negative → riskier
- **Monotonic WoE** across bins = the variable tells one coherent story
- **Information Value** ranks variables before any model exists

```
DSCR < 1.0   →  WoE −0.9   (danger)
DSCR 1.0–1.4 →  WoE −0.2
DSCR > 1.4   →  WoE +0.6   (comfort)
```

# From logistic to 300–850

1. Bin every feature → WoE-encode → logistic regression on WoE
2. Each bin gets **points**; a loan's score = base + sum of its bins' points
3. Scale so 50 points halves the odds (**PDO = 50**) → clamp to 300–850

| Band | Score | Default rate (your data tonight) |
|---|---|---|
| AAA | 750+ | ~2% |
| A | 700–750 | ~3% |
| B | 640–700 | ~4% |
| C | 580–640 | ~7% |
| D | <580 | ~28% |

**Monotonic bands are the sanity check that matters** — a validator reads this table before any AUC.

# The fitted model: coefficients and intercept

Release the machine on the same idea: optbinning re-optimizes the cuts, then one logistic
regression fits WoE → default.

$$\text{logit(default)} = \beta_0 + \beta_1 \times \text{WoE(bin)}$$

| | value | what it means |
|---|---|---|
| intercept β₀ | **−1.6053** | the book's own log-odds — ln(1,605 bad / 7,995 good) = −1.6057 |
| coefficient β₁ | **−0.9968** | ≈ −1 — WoE already carries the log-odds, so fitting barely rescales it |

**Points, not just PD:** `points = offset + factor × (−logit)`, factor = pdo/ln2 = 72.13,
offset = 600 − factor·ln(20) = 383.90 — the same PDO scaling, applied bin by bin.
